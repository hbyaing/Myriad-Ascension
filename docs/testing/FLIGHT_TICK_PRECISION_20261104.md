# 旧世界每 tick 前端伸缩与御剑尾迹长度跳变

状态：本地候选，未上传 GitHub。本轮从 `c8a2a5e` 接续，针对用户 `Base Profile 2026.11.04 - 19.59.30.01.mp4` 的前端约 50 毫秒伸缩、御剑拖尾忽长忽短。本轮正式源码仅修正历史路径的时间计算，没有调整亮度、材质、尺寸、相机、速度或筋斗云。

## 已确认的共同原因

原式 `double now=capturedTrailTick-1+partial` 中，`partial` 是 float。Java 先将长整数时钟转为 float 运算，最后赋给 double 已经无法找回丢失的小数。旧存档时间约一千万 tick 时，float 的间隔为整整 1 tick，历史路径的时间会在半 tick 附近直接跳变；模型、镜头挂点仍然保持平滑插值。

只读核查实际使用的存档 `测试 (1)/saves/新的世界 (4)/level.dat`：初次读取 Time=10,200,336，后续用户客户端自动保存时为 10,206,336。后一次源文件哈希及读取记录保存在本机 `reports/tick-root-20261104/actual-world-age.json`。没有修改原存档。DayTime 与总游戏时间不同，不能用当前白天/黑夜推断这个条件。

历史比挂点超前时，`renderNodes` 会将前方采样点与落后的渲染头连接，化虹便出现额外前伸段；普通御剑又把前方部分裁掉，且显示窗口随错误弧长移动，形成周期性缩短甚至几乎消失。这是几何路径问题，不能仅靠亮芯过滤或提亮解决。

修复新增 `SwordTrailPhase.renderTick(long,float)`，在相加前就使用 double 小数，并将御剑/化虹历史改为调用它。遁光历史中的同型表达式一并使用该函数；遁光的局部时钟通常较小，该项属于同类精度缺口修正，不是本轮原视频的主要触发点。其他绝对世界时间着色器未扩大修改范围。

此前新建测试世界的时间只有几百 tick，遗漏了旧世界的大时间戳触发条件。这是此前检查通过、实际视频仍有问题的关键验收缺口。本轮保留旧代码的真实失败基线，不用修复后的新世界替代该对照。

## 回归边界

`FlightLargeTickQa` 对实际历史代码测试 1440 个组合：新世界、实际用户时间、2^20/2^22/2^24/2^26/5000 万 tick；多种速度；60/120 FPS 的 tick 内相位。冻结旧表达式可重现 14.75 米向前越位、16 米窗口长度跳变；新函数前向越位为 0，尾边界最大误差约 5.96e-7 米，与新世界的几何/年龄协变误差约 1.49e-7。

新增实机断言检查实际传入几何的时间与共享姿态小数一致、最终历史头与挂点重合。不会把正常急转弯留下的远处历史轨迹错误地要求为始终在身后。详细顶点记录仍有限额，但前向范围统计覆盖全部符合条件的近头部顶点。

所有验收均使用独立客户端及禁止真实鼠标捕获保护。测试配置与时钟注入代码只在 QA 源集，不进入正式包。大时间戳和高度的复现不等于原存档的地形冷加载性能验收；用户现场是否仍有其他视觉问题仍需正式包复验。
