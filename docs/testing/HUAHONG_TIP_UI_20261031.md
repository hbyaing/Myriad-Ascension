# 化虹前端连续性与设置控件修复（2026-10-31）

本轮包含化虹前端抽搐、皮肤折叠选择，以及识海“创世 · 管理小世界”“天仙渡劫”按钮左侧空档三项。

## 原因与实现

- 首轮真实全速诊断发现本地载体在客户端分区停止更新后冻结，但特效历史时钟仍推进，`xOld` 与当前位置之间的旧区间被每 tick 重播。历史尾部与渲染头部倒向连接，换皮肤时头后 3 格的点可从后方翻到前方，出现约 6 格突变。`ControlledSwordEntity.isAlwaysTicking()` 仅让本地玩家所骑飞行载体持续消费客户端快照；服务端、攻击剑、远端玩家载体保持原行为，不新增区块加载或 ticket。
- 旧化虹路径仅插值中心位置；经过历史折线节点时仍直接切换切线，偏离中心线的亮筋与皮膜会跳动。生产路径改用相对坐标下的弧长窗口积分及其连续导数，局部头部和历史段之间的混合也使用真实导数。飞行速度、碰撞、消耗和网络缓冲不变。
- 局部核层的面向相机横积在沿轴追视时没有稳定方向。头核与局部白筋改用两张互相垂直、沿载体截面运输的光带，并分摊透明度；历史长尾保留既有绘制方式。
- 化虹皮肤默认只显示当前皮肤一个按钮，展开为紧凑选项网格，选择或 Esc 后收起，支持 Enter 展开。复用正式按钮与箭头，重建时校正焦点和拖动状态，动态内容高度由原宿主计算。展开后按实际视口自动滚动，使按钮和完整选项网格同屏可见。
- 识海两个入口的图标裁图本身含左内框；旧固定偏移叠出第二条内缩边。按批准源图提取清单恢复图标相对偏移及比例，外框素材不变。

## 连续性复现

`HuahongPathQa` 对生产 Java 路径进行圆弧复现，在每 tick 转 0.2 弧度、每 tick 位移 0.2 / 2 / 10 格的情形，以 0.0001 tick 步长检查跨节点、跨 tick 的截面和偏移顶点。

旧版本首次失败：速度 0.2、时间 10.0359、头后 0.8 格处，偏移顶点跳动 0.117457 格，截面相邻点积 0.989218。修复后 540,018 次转弯检查通过，最大偏移步进 0.001018 格、最大截面角步进 0.028203°；另有 196,128 次追视角及大转角检查和原有 8,666 次路径检查。该步长是数值连续性测试条件，不是实际帧率或性能报告。

本机旧代码复现与新代码结果分别保留于 `reports/huahong-tip-20261031/path-baseline/` 和 `path-fixed/`。

## 验收入口

```powershell
.\gradlew.bat verifyFull --offline --no-daemon --console=plain
.\gradlew.bat runClient -PmyriadCapture -PhuahongCapture -PhuahongSkins -PhuahongMotion -PhuahongFullSpeed -PheavenlySmallWorld -PhuahongOutput=reports/huahong-tip-20261031/native-final2 --offline --no-daemon --console=plain
```

外部光影另加 `-PmyriadExternalShaders`，在独立 `build/myriad-client` 中启用 Solas Shader V3.7b，输出目录改为 `solas-final`。`heavenlySmallWorld` 仅为识海两个真实入口加载本机可选创世仙途夹具，不是正式依赖。

全速夹具采用正式 1.0 速度倍率、高空连续环线及俯仰，不再反复传回起点；测试专用预热保证路径加载。`motion-metrics.json` 记录真实载体与共用路径的逐帧诊断，其他皮肤的 nose 字段是同一载体参照点，不能当作各皮肤最前网格顶点。

首轮 `native/` 不是通过证据：它记录并暴露了实体冻结，且 UI 截图存在补跑 tick 导致的阶段越帧。最终夹具等待截图被渲染帧消费后才推进阶段，并核验每张图片的实际尺寸与当前分页。运动断言除帧数、跨 tick、八皮肤外，还要求真实位移范围、转角和实体 tick 增长，拒绝静止重放。

`native-final/` 记录了实体更新修复后恢复的真实运动，但测试夹具等待区块时漏发输入，第四个皮肤因非稳定巡航失败；以补齐等待期间输入心跳和切换按键去重后的 `native-final2/` 为准。
