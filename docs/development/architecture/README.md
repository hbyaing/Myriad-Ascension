# 万界仙途持续架构优化工程

状态：协作工程已建立；结构方案为可修订建议，Java 改造与效果验证尚待逐项实施。

建立日期：2026-11-05。建立时主线：`1adfa2d`。维护状态见 [任务清单](TASKS.md)。

## 共同目标

在保持用户确认的玩法、存档兼容和协作者工作成果的基础上，让新增内容更容易接入、修改影响更可控、故障更容易解释、资源成本更可见，并允许未来替换规则与实现。

架构优劣通过实际需求衡量：相关改动需要理解和修改哪些地方、怎样证明实际生效、失败如何恢复，以及实现和维护成本是否合理。目录数量、文档数量和接口数量不作为完成标准。

本项目为架构优化提供共同入口，不要求其他玩法工作等待它，也不要求所有 AI 采用同一内部实现。用户决定目标、玩法含义及重要取舍；开发者和 AI 负责调查、推荐、实现和验证。可查事实自行核查，普通实现选择在授权范围内推进；影响玩法或重要兼容承诺时用具体例子说明并取得必要决定。

本轮用户明确授权上传这组协作材料。后续代码制作、验收与上传遵守当时用户指令及仓库最新 AGENTS；本文件不恢复已被新约定取代的自动推送规则，也不授予任意改玩法、删资源或重写存档的权限。

## 五步推进，按任务循环

| 步骤 | 阶段目标 | 实际成果 | 结束条件 |
|---|---|---|---|
| 1. 确定现状 | 建立可信且足够小的改造基线 | 相关源码入口、当前行为、状态责任、运行环境和已有失败 | 新接手者能定位入口并复现相关基线；未跑项目明确标记 |
| 2. 完成局部改造 | 解决一个已经发现的结构问题 | 一个范围受控的实现、兼容措施和对应验证 | 正常与关键失败路径通过，改动可独立解释和回退 |
| 3. 检验跨领域扩展 | 用第二种需求挑战已选边界 | 目标矩阵或跨领域功能、消费者检查、增量成本记录 | 新需求可接入，原消费者语义保持，证据不足的抽象撤回或保留局部 |
| 4. 沉淀稳定能力 | 将已证实的共同责任做成可复用入口 | 必要公共接口、局部依赖检查、准确导航和附属接入说明 | 至少由实际消费者验证；不为未知用途强建通用框架 |
| 5. 持续维护 | 随新增需求治理复杂度、资源与兼容 | 有依据的下一任务、迁移/回退记录、资源和性能基线 | 每批有明确完成点，收益不足或风险更大时调整路线 |

五步是每批工作的推进方式，不是必须先扫完整仓库再开发。资源与性能计量可与领域任务并行。持续优化没有预先承诺的“永久完美”终点，但每个任务都必须有有限的验收目标。

## 首轮目标

首轮拟回答：现有 V5 开炉入口能否在保留日志、领取和恢复语义的前提下，让调用者可靠识别拒绝原因及提交后的异常？

先完成构建基线和调用者调查，再决定最小改动。不能把原 boolean 统一替换为 FAILED 枚举后认定优化完成；“未提交的拒绝”和“已写入后发生异常”要求不同的后续行为。

独立候选包括法宝—御剑目标矩阵、持久化 I/O 测量、资源制品账本。它们不必等炼丹全部改造完毕；存在同一规则或状态冲突时才协调先后。

## 让其他 AI 自由参与

1. 阅读与任务相关的现行源码、AGENTS、任务清单和已有证据。V0.3 是参考，不能替代调查。
2. 选择现有任务或补充一个有明确问题依据的任务。登记负责会话/分支、基线、所改规则/状态/协议和文件范围，帮助他人发现重叠。
3. 使用独立分支或合适工作区保存自己的改动；不覆盖他人的未提交文件，不强推主线。
4. 登记是协调信息，不是全局锁，也不保留无限期独占权。过期任务先核对实际分支和负责人状态，不擅自标记别人完成或放弃。
5. 无共享语义影响的任务可独立推进；共享 API、存档或协议变更先提供具体影响说明。Git 没有冲突不代表玩法没有冲突。
6. 可以提出替代方案、缩小公共抽象或保留局部实现。比较时承担同样的旧行为、失败、恢复和验证责任。
7. 完成后提交结果、证据与未覆盖项；合并到新主线后按影响重验。发布和安装按当前授权处理。

任何人无需为了贡献一个普通内容填写全仓表格。任务记录只保留本次会改变判断的字段；源码索引、操作结果和诊断能自动生成或检查时逐步自动化，业务语义仍需审核。

## 任务记录的最小形式

```text
任务 ID / 问题：当前行为或结构造成什么困难
状态 / 负责者 / 基线：谁在何版本上处理，分支或会话位置
预期结果：玩家或调用者能够观察到的变化
影响范围：规则、状态、协议、资源、文件和实际消费者
不变项与未知：需保留的行为，以及尚不能确认的事实
方案与取舍：直接实现、复用或新增机制的理由
验证与证据：真实入口、正常/失败路径、命令、日志、版本
交付与回退：提交、采用状态、迁移责任、撤销边界和下一步
```

状态使用：候选、调查中、实现中、待验证、待验收、已集成、暂缓。候选不是已授权的任何实现；已集成不是全部玩法或长期收益已验证。只有实际开展才填写负责人。

## 证据和收益

- 行为证据：编译、规则测试、GameTest、客户端与存档恢复分别说明覆盖范围。
- 结构收益：共享热点修改数、实际消费者范围、理解与排错步骤、第二份需求的增量改动。
- 成本证据：构建、运行 Tick、网络、渲染、磁盘 I/O、生产 JAR 和资源，按任务相关性测量。
- 兼容证据：旧数据、旧调用者及第三方交互；未覆盖部分明确列出。

不设未经测量的百分比目标。先记录前后同等条件；抽象没有降低总成本时允许撤回。代码回退与已迁移存档回退分别说明，不能承诺 git revert 可撤销所有数据变化。
